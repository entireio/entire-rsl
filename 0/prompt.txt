```
// The actor field is the pusher field's orthogonal counterpart: pusher names the
```

The constants are at lines 101-107, with the comment that the labels "deliberately omit the underlying technical identity (workload SPIFFE name, service-account ULID, automation id)".

- **`entire-mirror-service`**: an internal workload whose handle is the mirror-worker workload.

- **`entire-automation-service`**: a principal of kind `KindAutomation`.

- **`entire-trust-service`**: policy publication (trust management). Lines 399-404 explain it: "the trust-management publication path (PublishPolicy), whose baseline entries are attributed to the trust service regardless of which principal triggered the publication. These baseline entries have no operation field.

## 4. How a repo's root of trust is created

**Who holds the root key.** A single fleet root, kept on the server (`custody: server_held`, threshold 1; clusters.prod.yaml:9-23). Its seed is stored encrypted with KMS in Secrets Manager. It is fetched per generation by `core/trust/rootseed_provider.go:12-20` and unwrapped inside entire-core. `core/trust/author.go:62-89` checks it against the reviewed profile key before signing anything.

**What gets authorized.** `core/trust/policyrequest.go:92-149` (`AuthorPolicyRequest`) includes every `pending` and `active` signer from every cluster the repo is placed on (primary plus native mirrors), and leaves out `retiring` signers. It fails if any placement has no authorized signer.

**Building the signed policy.** `core/trust/author.go:101-131` builds a `gittufstore.AuthorPolicyInput`. For a first bootstrap it calls `gittufstore.AuthorBootstrapClosure`, which creates a policy commit with no parent; later changes use `AuthorSuccessorClosure`. `gittufstore/closure.go:160-168` then calls the fork's `policy.Author` (in place of `policy.Bootstrap`):
```go
treeID, err := policy.Author(ctx, store, policy.BootstrapParams{
    RootSigners:         []crypto.Signer{rootPriv},
    RootPublicKeys:      cryptoPublicKeys(in.RootPublicKeys),
    RootThreshold:       in.RootThreshold,
    RSLSignerPublicKeys: cryptoPublicKeys(in.RSLSignerPublicKeys),
    RefPatterns:         in.RefPatterns,
    ...
```

**Inside the fork** (`pkg/policy/policy.go`):
- The root keys go into both the root role and the primary rule file, with the root threshold (lines 641-664).
- The RSL signers are added as principals in a single targets rule: `const rslSignerRuleName = "authorize-rsl-signers"` (line 63), created with `targetsMetadata.AddRule(rslSignerRuleName, ids, p.RefPatterns, p.rslSignerThreshold())` (line 682). The RSL signer threshold defaults to 1 (lines 456-462).

**RefPatterns: `git:refs/*`.** Set at `/home/coder/git/entirehq/entiredb/internal/entirecore/trust_reconciler.go:58`:
```go
func trustReconcilerRefPatterns() []string { return []string{"git:refs/*"} }
```
The comment at lines 43-57 says this is intentionally the all-refs wildcard rather than the narrower set the ADR targets ("refs/gittuf/policy + refs/entire/checkpoints/* + refs/tags/* + default branch"). Narrowing is tracked in ENT-1605. The value is passed in at line 541 through `nativemirror.TrustReconcilerConfig.RefPatterns`.

**Expiry.** Defaults to 10 years (`core/nativemirror/trust_reconciler.go:236`).

**Publication.** `rslstore/publish.go` `PublishPolicy` (line 103) does a compare-and-swap on `refs/gittuf/policy`. On bootstrap, `recordBaseline` (lines 264-330) throws away any RSL entries written before the policy and starts the baseline at entry 1. Those baseline entries carry the `entire-trust-service` actor.

**Per-repo state.** Lifecycle states are `disabled` → `bootstrap_pending` → `rooted` (`rslstore/writer.go` `LifecycleFunc` comment). Admins trigger rooting with `POST /api/admin/repos/{repoID}/enable-trust-root` (`core/api/server.go:1674`). The procedure is in `docs/runbooks/rsl-bootstrap-production.md`, which I did not read.
